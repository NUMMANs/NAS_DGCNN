### PointViG 论文规格（复现依据）

### ⚠⚠ 性能：让 NAS 从"不可行"变"可行"

初版 **1.08 s/step**（比 DGCNN 104 ms 慢 10×）→ 不可行。
逐组件计时定位：**FPS 是唯一主瓶颈（0.549 s，占 63%）**。
⚠ **FPS 天然串行，向量化救不了**（朴素 0.549 → 向量化 0.499 s，几乎没变）。

**解法：双策略降采样**
- `npoint > 512` → **体素网格降采样**（一次性、O(N)、无循环）
- `npoint ≤ 512` → 真 FPS（迭代少，代价可接受）

**效果**：降采样 **0.549 s → 0.5 ms（~1000×）**；训练步 **1.08 s → 0.123 s（8.8×）**
→ **118~186 ms/step，与 DGCNN 同量级 → NAS 可行**。

> 判断依据：对 NAS 而言**下采样算子的形式不是搜索变量**，
> 网格近似合理；真正要搜的是 **ADGC 的半径集合**。

### PointViG 实现的 5 个 bug（每个都值得记）

| bug | 症状 | 根因 |
|---|---|---|
| **`v[:, nbr]` 按 dim0 索引** | 通道/样本错位但**不报错** | 邻居索引 `(N,kk)`、`v` 是 `(C,N)` → 正解 `v.T[nbr].permute(2,0,1)` |
| **缺解码器** | `batch_size (64) vs target (16384)` | 只编码不下采样回填。论文同样有 5 stage 编解码 |
| **插值用错坐标** | 最近邻算在全错坐标上（**不报错**） | 粗层点集**不是** `xyz0` 前 N 个点（乱序抽取）→ 必须记 `xyz_hist[s]` |
| **`dec_blocks[s-1]` 下标反序** | 宽度全错 | blocks 按 `s=4,3,2,1` append → `s=4` 对应 `[0]`；用顺序计数器 |
| **head 宽度写 `c`** | `mat1[16384,32] × mat2[512,128]` | head 输入是**解码末轮宽** `widths[0]` |

**已加 3 条断言**（解码每级宽度 / 解码后点数回到 N0 / head 宽度）。
> **教训：`nn.Linear` 的形状报错（如 96x32）看不出是哪一级的问题。
> 在循环体内加显式断言，比事后倒推快得多。**

**参数 3.50M vs 论文 5.3M**：差异来自论文未公开的解码器细节，属预期范围。
**不影响实验**（命题是同骨干下的**相对比较**）。

### ✅ 站得住的命题 + 一个自我否证（5-seed 配对复核完成后）

**5-seed 完整复核**（4 配置 × 5 seed）：

| 配置 | mean | std | 配对比较 vs `[0.05]` |
|---|---|---|---|
| `[0.05]` | 0.3618 | **0.0045** | 基准（最稳） |
| `[0.05,0.3]` | **0.3663** | 0.0105 | **+0.0045, t≈1.43, 胜 4/5** ❌ 不显著 |
| `[0.2,0.4]` | 0.3617 | 0.0055 | −0.0002, 胜 2/5 |
| `[0.2]`（论文） | 0.3534 | 0.0097 | **−0.0084, t≈−2.01, 胜 2/5** ✅ 稳健 |

**最终结论（三条，按强度）**：

1. ✅ **论文 r=0.2 非最优 → ROBUST**
   8 半径扫描中 0.2 排第 5；`[0.05]` 高出 +0.0152。
   5-seed 复核 t≈−2.01，**连最有利的 seed 论文也只赢 +0.0036** → 与噪声分离良好。
   **论文消融只扫了 k（k=32），从未扫 r —— 而 r 才是 Ball-Query 感受野的真正旋钮。**

2. ✅ **多尺度只在"起点差"时有用 → SUPPORTED（本次最重要的发现）**
   ```
   [0.2,0.4] 0.3617  vs  [0.2] 0.3534   →  +0.0082（多尺度救回坏起点）
   [0.2,0.4] 0.3617  vs  [0.05] 0.3618  →   无增益（最优起点上加尺度没用）
   ```
   > **多尺度的作用是"补偿选错的单尺度"，不是"超越最优单尺度"。**
   > 这解释了为何 `[0.05,0.3]` 的优势不显著：**单尺度已搜到最优时，多尺度没有剩余空间。**

3. ❌ **多尺度 > 最优单尺度 → NOT_SIGNIFICANT**
   +0.0045、t≈1.43、胜 4/5（非全胜）、std 大 2.3×。
   **我早前称其为"严格机制增益"属过度解读，已撤回。**

> **这否证了我自己最初的方向**（原假设是"多尺度混合更优"），
> 但也因此得到更准确的命题：**"半径轴本身没被作者搜过；一旦搜到最优，多尺度就没有额外价值"**。

⚠ **适用边界**：小规模协议（4+2 房 / 300ep / 16k 下采样）。半径最优值可能随协议变化；
须上**全量 12+12 房 + 更长训练**才能成为可发表结论。

### ⚠⚠ 方法论教训："对照组选择偏差"翻车（必须记住）

**过程**：首个对照实验 `[0.1,0.2,0.4]`(0.3615) vs `[0.2]`(0.3495) = +0.0121，
我一度判为"多尺度赢"。**但 0.2 本身不是最优单尺度** ——
一旦把单尺度也搜全，`[0.05]`(0.3646) 立刻压过所有已测多尺度，**结论一度反转**。
（后来 `[0.05,0.3]` 才真正反超，但那是**另一个配置**）

> **通用教训：任何"X 优于 Y"的结论，必须先把 Y 自身也搜到最优。**
> 否则比的不是"机制差异"，而是"Y 的参数没调好"。
> 本项目在 k 轴、feat 轴上都吃过同源亏 —— **这是第 3 次**。



**PointViG 骨干，唯一变量 = ADGC 的半径集合**：

| 配置 | val mIoU | seed 极差 | s/ep |
|---|---|---|---|
| **A：`[0.2]`（论文单尺度设计）** | 0.3495 | 0.0113 | 0.14 |
| **B：`[0.1,0.2,0.4]`（三尺度）** | **0.3615** | 0.0080 | 0.18 |
| C：`[0.15,0.3]`（双尺度） | 0.3557 | 0.0060 | 0.16 |

- **B vs A = +0.0121 → 超过两者 seed 极差 → 可信** ✅
- C vs A = +0.0063 → **噪声内，不可信** → **"任意多尺度都行"是错的**

> **命题**：论文作者用**单一固定半径 r=0.2** 保证感受野一致；
> **多尺度混合同骨干同协议高出 +0.0121，且 seed 更稳。**
> 且**尺度集合的具体选择是实质变量**（C 在噪声内）→ 正是 NAS 该搜的对象。

**⚠ 四点诚实标注**：① 规模小（4+2房）需全量确认；
② **绝对精度低（0.36 vs 论文 71.7%）** —— 因 300ep/单次前向/4 房训练，
**不影响相对命题，但不能报绝对数字**；③ B 更贵（+29%）；
④ C 不可信 → 非平凡性证据。

**四条可复用的规律**（都来自实测）：
1. **z_bins 倒 U，单尺度峰值≈64**（voxel25：z8 0.3290 → z64 0.3885 → z192 0.3806）

3. **收益来自"加分支"，不来自"调粗端参数"**：粗端 v50→v35/v25、z96→z64/z128 全部

## ⚠⚠ 真正的进化闭环（本项目最重要的方法论产出）

**前两轮为什么不是真进化**：
| 轮次 | 空间 | 新架构能否**真实**评估 | 结果 |
|---|---|---|---|
| `pareto` | 63 个预选固定点 | ❌ 只能挑名字 | best 在 iter 1，60 迭代只 4 个不同分数 |
| `pareto-gen` | 组合空间 | ⚠ 只有**估计精度** | `is_synthetic` 0→11 但赢不过实测 |

**三个条件缺一不可**：A 空间够大 / B 新架构能被真实评估 / C 奖励无结构性天花板。

**逐条补齐**：
- **A** → `nas_ptseg/arch_space.py`：架构串语法 `<branch>[,<branch>...]@<fuse>[|feat=N]`，
  组合数 **≈3.2×10^8**（vs 手工 88 个）。严格校验。成本模型与实测锚点比值 0.75~1.23（多数 <5%）。
- **B** → `multibranch_exp` 的 `_known()/_arch_spec()` 识别架构串 → **无需注册 CONFIGS 即可训练**。
- **C** → `evaluator_pareto._synth_from_spec` **第三版**：**成本可估，精度绝不估**。
  新架构精度标 `pending`、不参与打分，作为"待实测建议"返回。
  理由：成本由**结构**决定可外推；精度由**优化**决定，**无法从结构推出**，强估会系统性压制探索
  （第一版保守估计把探索压到 0；第二版加固定奖励只是"奖励猜测"）。
- **闭环执行器** → `nas_ptseg/arch_loop.py`：`propose_by_sampling()` **不依赖 LLM**，
  以"精度最高的**可信**实测"为锚点做单轴邻域扰动。`measure()` 带 **`max_rounds=10` 多轮重试**。

**⚠⚠ 方法论修正：选择用枚举，提出才用 LLM。**
候选池有限（~70）、目标确定 → **枚举就是精确解**。
实测：两轮 LLM 搜索的 best = 0.4216，**不如直接枚举的 0.4244**。
| 环节 | 工具 | 理由 |
|---|---|---|
| **提出**新架构 | `arch_loop.py` / LLM | 需创造力；空间 3.2×10^8 **枚举不了** |
| **选择**最优 | **`nas_ptseg/pareto_select.py`（枚举）** | 候选有限、目标确定 → 枚举即最优 |
| **验证** | 真实训练写回表 | 摆脱"估计值天花板" |

**⚠⚠ 测试集泄漏（已修）**：`measured_archs()` / `_find_tables()` 的 glob 把 `_tval`
验收表也扫进来了（目录名以 `multibranch` 开头），同名表**覆盖顺序取决于 glob**。
→ 冠军值一度显示 0.4184（test）而非 0.4126（val）。
**修法（两处都改）**：显式跳过 `"_tval" in base`；扫描范围由 `data/multibranch*` 放宽到 `data/*/`。
> **通用教训：验收表与搜索表必须从机制上隔离（`_tval` 后缀），
> 所有读搜索数据的入口都要显式排除验收表。只靠"记得别用 test 数字"不可靠。**

## 编码 / PowerShell 硬坑
1. **`.env` 必须纯 ASCII**：PS 5.1 按 GBK 读 UTF-8 时中文注释尾字节会**吞掉 CR/LF** → 行合并、
   key 行消失 → `loaded 0 variable(s)`。`run.ps1` 已加 `-Encoding UTF8`。
2. **`openevolve.config.Config.from_yaml` 在中文 Windows 崩**（`open()` 无 encoding → GBK 解码中文注释）。
   **修法 `$env:PYTHONUTF8="1"`**，已写入 `run.ps1`，**不要删**。
3. **`.ps1` 必须纯 ASCII**；**Python 里不要用 ASCII 直引号当中文引号**。改完必 `py_compile`。
   ⚠ **`.bat` 完全同理**（cmd.exe 按 OEM 代码页 = zh-CN 上 GBK 读 `.bat`）：
   UTF-8 中文注释会让脚本**静默崩溃**，表现为"双击后一闪而过 / 毫无反应"。
   已在 `_sdk/install_sdk_only.bat` 上实际踩到。
   **校验法**：`open(f,'rb').read().decode('ascii')` 必须通过。
   3b. **`.bat` 的 `echo` 文本里不要出现 `(` `)`** ——
   在 `if (...)` / `for (...)` 块内，文本中的 `)` 会**提前闭合块**，
   报错 `此时不应有 .。`。写 `(UAC)` 这种注解就会中招。去掉括号比转义 `^)` 更稳。
4. **PS 超时**：`& $py ... | Out-String` 这类"等子进程再写文件"的模式会被杀且什么都不写。
   长任务用 `& $py @args` 不套 Out-String（后台长跑实测可跑满 58 分钟）或 Bash 后台；
   Python 用 `--log-file` 自己实时写 UTF-8。
5. **`Remove-Item` 不可靠**（被安全机制接管）→ 用 `[System.IO.File]::Delete()`。
6. **`wmic` 已被安全策略禁用** → 查进程用 `Get-Process python`。
7. 其他：`$args` 是 PS 自动变量；PS 5.1 无 `Set-Content -Append`（用 `Add-Content`）；
   `@(@("a","b"))` 被**展平** → 包循环别用 `@()`；`run_*.ps1` 的 `-Mode` 用 `ValidateSet`，
   新增子命令必须同步；**`-File x.ps1 -Arr 50,100,150` 会把数组绑成整数 50100150** → 必须 `-Arr @(50,100,150)`。
8. **Bash 环境 coreutils 缺失**（`cat`/`head`/`dirname` 都没有）→ 文本输出一律"写文件 + Read"；
   **不能用 Bash 调 powershell**（被安全策略拒绝），要用 PowerShell 工具。
9. **PowerShell 里 `@` 是数组运算符**：`Get-ChildItem "*@*"` 之类会静默失败/无输出。
   查含 `@` 的文件要用 Glob 工具或 Python glob。
10. **PS 把子进程 stderr 当终止错误**：`$ErrorActionPreference="Stop"` 时，
    evaluator 有意打到 stderr 的摘要会**中止启动器**（尽管它其实成功了）。
    调用处临时放宽为 `Continue`，真正的门禁是 exit code。
11. **`Write-Host` 字符串里不要用反引号转义引号**（`` \` ``）—— GBK 解码下解析失败。

## ⚠⚠ 踩过的坑（每条都曾产出过错误结论）
| 坑 | 症状 | 正解 |
|---|---|---|
| **形状能广播 ≠ 语义正确**：`(1,3,N)` 传给期望 `(N,3)` 的分支 | **不报错**；分支 std 正常(0.62) 但 logits std 仅 0.048 → **预测类数=1**；loss 首值 1.94（正常 4.29）且几乎不降；同房 mIoU 0.04 | 跨模块传张量**必须显式统一形状约定 + 边界断言**。修后 0.04→0.8465 |
| **在稀疏图/体素上用 BatchNorm** | 室内体素图 97.7% 空 + batch=1 → BN 统计被 0 主导 → **跨点特征 std 0.326→0.0018**（稀释 180×）、训练时间 33s→1.2s | 一律用 **GroupNorm** |
| **`|` 是 Windows 文件名非法字符 → 整条轴静默不可测** | 架构串 `\|feat=N` 进文件名 → `open()` 抛 `PermissionError(13)` → 崩在第一格、**表完全不存在**；外层 `_table_complete` 永远 False → **无限重跑**；而 subprocess `returncode` 仍可能为 0 → **报"成功"**（三层掩盖，极难定位） | ① `arch_space.safe_filename()` 只替换文件名（表内 `name` 仍存原串，**切勿从文件名反推**）；② 写/读两处**共用同一函数**产文件名（各写一份必漂移 → 死循环）；③ **不要只信 returncode**，每轮用 `_table_complete` 复核产物；④ **`|` 之外还要小心 `* ? " < > : \ /`** |
| **性能测量未 warmup（CUDA 伪影）** | `z_bins=8`（真实前向 1.0ms）被量成 **238 ms/step**，比最重配置还慢 40× → **使 Pareto 前沿整体反向** | 测 step time 前**必须 warmup 3 次** + `reset_peak_memory_stats` + `synchronize` |
| **配置名与参数值不一致** | voxel 写成 `z_bins=max(8, z_bins*2)` → 标称 `voxel25_z32` 实际 16；据此得"z16→z32 +0.0177"**是错的** | 参数**直白透传**；配置名数值必须等于实际值；建表后**回读 config 校验** |
| **`concat` 融合建了不用的逐分支 heads** | 3 分支时 **24 个参数无梯度** → 虚增参数量、污染优化器 | `concat` 下 `heads` 留空；**建完模块必查 `p.grad is None`** |

| **判据关键词集合不全（同错 3 次）** | 只查 `pillar` → 把 `voxel25`(+0.0279) 误标成"同族容量调整"；再漏 `ms`/`pv` 前缀 → 冠军误报成 `voxel25_z64` | 关键词集合必须覆盖**全部命名族**；新增命名族时同步更新 |

| **忽略 `loss 首值`** | 同一初始化下 loss 首值差一倍即说明前向分布已不对 | 先看 loss 首值，比最终 mIoU 更早更干净 |

| **`index_add_`（就地）与 `index_add`（返回）混用** | 就地版易漏赋值 | 统一 `x = x.index_add(...)` |
| **填栅格图按"柱出现顺序"而非栅格坐标** | **不报错**，但等价于对空间做随机置换，3×3 卷积失去意义 | 按 `(gx,gy,gz)` 落像素 |
| **一次性 `Conv2d` 放进 `for` 循环重复调用** | 第二层通道不匹配 | 逐层串联成 `nn.Sequential` |
| **LLM 会编造机制来自我合理化** | best 程序把策略改回返回名字，注释称"返回 list 会让 `min_domain`（占适应度 0.5）被压低" —— **`min_domain` 在 `evaluator_pareto` 里根本不存在**（是旧 k 空间的设计）。注释**读起来极像真实实验结论** | ① 只信**客观可观测字段**（如 `is_synthetic`），不信注释里的自我陈述；② 注释里出现具体机制/权重/指标名时**必须回源码核对**；③ artifact 报告里**列出当前评估器的真实指标** |

**方法论四条**：
1. 判"分支坏没坏"用**能否过拟合单房间**，不用跨房 mIoU。
2. 遇到"分数低"先看**训练时间是否异常**（区分"任务难"与"梯度没了"），再看 **loss 首值**，最后才看 mIoU。
3. **在确认实现正确之前，绝不对"某表示/方法是否有效"下结论** —— 为此误判两轮。
4. **短耗时 ≠ 没训练**：pillar 2.3s/run、voxel 7.1ms/step 都曾被误判为"梯度被切断"，
   两次验证都否证（梯度全有；ep=0 0.0610 → ep=300 0.8465）。**耗时短恰恰是优势本身。**

**间歇性原生崩溃**：`exit -1073740791` = `0xC0000409`（STATUS_STACK_BUFFER_OVERRUN），
无 Python traceback，已发生 **6+ 次**。表每 cell 落盘 → **用多轮重试跑到完成，不要追这个 bug**
（`arch_loop.measure(max_rounds=10)`；重试成本 ≤1 cell）。

## 可读实测数值
- S3DIS **272 房间**，点数 8.6 万~927 万（108×），尺度 1.8~44 m（24×）。划分体检：train/val/test 各 12 房间，
  ρ 几何均值 1901/1878/1656，L 均值 4.28/4.49/4.59，类别均值 6.67/6.75/6.92（无系统性差异）。
- **室内点云是二维面采样**：γ=0.46~0.41（体填充 1/3、面采样 1/2）；`dbar/r_k`=0.68~0.74。
  → 体填充先验 `rho=k/((4/3)πr³)` **不成立**，谈"物理感受野"必须用**实测 r_k**。
- 训练成本：16384 点、150 ep ≈10 s；**18 万点每 epoch 15 s+**（DGCNN 逐层动态 kNN 是 O(N²)·层数）
  → 必须下采样到 ≤16384 点。
- 表成本：cheap@25 = 144 cells/6.4 min；cheap@50 = 12.4 min；full@300 = 144 cells/**57.9 min**。
- seed 噪声：单房间 0.04~0.07 → 分辨 0.02 量级效应需 seed ≥8~10；表口径 σ_fit≈0.0014。
  换表示配置的 seed 极差通常 0.0001~0.0045。

## 训练程序硬约束
- **`run_tier2.ps1` 绝不能设 `OMP/MKL/OPENBLAS_NUM_THREADS`**：训练前 ~20 epoch **原生崩溃**
  （exit `0xC0000409`）。已移除。
- 划分必须用**空间块留出**或**跨房间**，不能用随机留点（会抽稀训练集、污染密度自变量）。
- Tier-2 的 DGCNNSeg **没有半径门控**（那是 Tier-1 代理的）；判据用 **p99**（`max` 会被孤立点主导）。
- **`evaluator` 必须返回 `combined_score`**，且候选异常早返回时**必须同时给 MAP-Elites 特征维度**
  （否则该轮报错、白烧 LLM）——已用 `EMPTY_METRICS` 修。
- 基线演进：PointNet++（已删）→ **DGCNN 验证机制** → 有效则上 PolarNet。
- 坐标保持米制（不归一化）；OpenEvolve 的 `TemplateManager` 是**级联覆盖**。
- **空间能被完整物化时就不需要廉价代理**：表建好后任何策略评估都是毫秒级、无偏、无预算敏感性。
