# Geometry-Search: 以几何表示为搜索对象的点云分割架构搜索

## 摘要

**问题.** 室内点云分割的骨干网络长期由离散点上的 kNN 动态图主导。这类网络的**感受野由近邻数 k 决定，因而随点密度漂移**——而室内扫描的点密度在同一数据集内可相差两个数量级。密集处邻域被过度填充，稀疏处邻域被掐断，同一个 k 无法同时适配两端。

**缺口.** 现有工作将这一矛盾归因于超参数选择，并在"k 取多少""池化用 max 还是 mean""图在坐标空间还是特征空间"这一层反复搜索。我们在一个受控的架构表上给出结论：**这一层的选择空间已被穷尽**——6 个配置（参数量完全相同）中，池化的主效应达 0.07，但**逐房间 oracle 相对最好单一配置的收益是 +0.0000，逐 Area（6 个）的最优配置完全一致**。也就是说，调参能选出一个更好的普通网络，但调参**无法**让网络适配条件。问题不在"选哪个超参"，而在"用哪种几何表示"。

**思路.** 我们改变搜索对象：不再搜索骨干的结构超参，而是搜索**几何表示与尺度本身**——把点云并行投影为多个体素栅格，每个栅格拥有自己的体素边长与 z 向分层数，并把"分支数量、各分支几何参数、融合方式"整体作为搜索变量。这一空间的组合数约为 **3.2×10⁸**，远超人工枚举所能覆盖。

**方法.** 为在该空间中搜索，我们建立一条**真实评估闭环**：候选架构以字符串形式表达、免注册直接训练、结果按单元落盘、评估器只估成本而**绝不估精度**（精度必须实测）。这一设计使新架构能够凭实测结果胜过任何既有配置，而不受"估计值天花板"压制；选择环节用枚举求精确解，提出环节保留创造性搜索。

**最硬的结果.** 在 S3DIS 上，以 12 训练房 / 12 验证房 / 2 seed / 300 epoch 的跨房间协议：

- **mIoU 0.4210（独立 test split），基线 0.3432，Δ = +0.0777（+22.6% 相对）**
- **训练快 2.8×**（37.5 ms/step vs 104.1），**显存省 7.5×**（470 MiB vs 3524）
- 冠军配置 **`voxel15_z16, voxel20_z24, voxel25_z16, voxel35_z64, voxel50_z96@gate`**：
  **五个不同体素尺寸（0.15/0.20/0.25/0.35/0.50 m），每层各自独立的 z 分层（16/24/16/64/96）**
- 该配置**由闭环自动搜出，非人工设计**；人工枚举 88 个配置的最好结果是 0.4110，**闭环在此基础上再推进 +0.0100**
- **test 上的架构排序与验证集排序完全一致**，增益随演化单调上升

**一句话.** 把搜索对象从"骨干超参"换成"几何表示与尺度"，并在 3.2×10⁸ 空间中做**真实评估**搜索，可在精度、速度、显存三个维度上同时支配 kNN 动态图基线。

## 1. 引言

### 1.1 一个被归错因的矛盾

室内点云的**密度异质性**是分割任务的核心困难之一。同一场景内，近处墙面每平方米可采样数千点，远处角落仅有数十点。以 kNN 动态图为主干的网络，其感受野半径近似为 `r_k ∝ (k/ρ)^(1/2)`（面采样下）——**k 固定时感受野随 ρ 反向漂移**。

社区对此的常规应对是在 k 这一层做搜索。我们对该层做了系统排查（§3），结论明确：

| 排查角度 | 结果 |
|---|---|
| 密度 ρ 与最优 k 的关系 | R² = 0.008 |
| 尺度 L 与最优 k 的关系 | R² = 0.018 |
| 类别数与最优 k 的关系 | R² = 0.001 |
| 逐房间自适应 k 的空间上限 | **+0.0017**（< 拟合噪声 σ=0.0014） |
| 逐房间/逐域条件化架构的空间上限 | **+0.0000** |

**在 k 与结构超参这一层，条件化没有可搜的空间。** 这一结论反过来指明了方向：既然"让同一个网络适配不同条件"行不通，那么**应当让表示本身与尺度解耦**——这属于**表示层**而非**超参层**的改动，其差异是族级别的。

### 1.2 为什么表示层是族级别的差异

| | 笛卡尔点 + kNN 动态图 | 体素栅格 |
|---|---|---|
| 感受野由什么决定 | **kNN 邻域，随密度漂移** | 栅格边长 × 卷积核，**与点数解耦** |
| 对密度下降的响应 | 邻域被掐断 → 特征退化 | 占用率变化，拓扑不变 |
| 归纳偏置 | 局部置换不变 | 尺度一致的规则结构 |
| 代价 | 逐层动态 kNN，O(N²)·层数 | 稀疏 3D 卷积 |

"与点数解耦"是关键：它把感受野从**数据分布的函数**变成**架构自身的常数**。

### 1.3 搜索对象的重定义

由此我们把 NAS 的搜索对象整体换掉。一个候选架构被表达为：

```
<branch>[,<branch>...]@<fuse>[|feat=N]
```

其中每个 branch 自带几何参数（族、体素边长、z 分层数），`fuse` 控制融合方式。例如冠军：

```
voxel15_z16, voxel20_z24, voxel25_z16, voxel35_z64, voxel50_z96 @ gate
```

搜索空间组合数约 **3.2×10⁸**（对比人工枚举的 88 个）。

### 1.4 为什么必须"真实评估"

搜索这么大的空间，天真的做法是用一个廉价代理预测精度。我们实验证明这条路会**系统性压制探索**：

| 代理策略 | 后果 |
|---|---|
| 用保守估计填补未测架构的精度 | 探索被压到 **0 次**（估计值永远不敢超过已测项） |
| 给未测架构加固定探索奖励 | 只是"奖励猜测"，仍非"奖励发现" |
| **成本可估，精度留空**（本文做法） | 新架构必须实测才获得分数 → 可凭真本事胜出 |

**原则：成本由结构决定，可稳定外推；精度由优化过程决定，无法从结构推出。**

### 1.5 贡献

1. **否证了结构超参层的条件化假设**（§3）：逐房间/逐域 oracle 收益 **+0.0000**，6 个 Area 最优配置完全一致，池化主效应虽达 0.07 但零交互。
2. **重定义搜索对象为几何表示与尺度**（§4），空间规模 3.2×10⁸，并提出**真实评估闭环**（免注册训练 + 逐单元落盘 + 精度绝不估计 + 枚举选择）。
3. **给出在精度、速度、显存三维同时支配基线的架构**（§5）：test Δ = **+0.0777（+22.6% 相对）**，快 **2.8×**，省显存 **7.5×**。
4. **提炼四条可复用的尺度规律**（§6），均来自实测，且解释了为何"越多越好/越细越好"是错的。

## 2. 方法：真实评估闭环

闭环由三段构成，每段都有明确的职责边界：

| 环节 | 职责 | 关键设计 |
|---|---|---|
| **提出** | 生成候选 | 架构串语法；以"精度最高的可信实测"为锚点做单轴邻域扰动；空间 3.2×10⁸ 无法枚举，故保留创造性搜索 |
| **实测** | 获得真值 | 架构串**免注册直接训练**；结果**逐单元落盘**（崩溃最多损失一个单元）；多轮重试 |
| **选择** | 求最优 | 候选池有限、目标确定 → **枚举即精确解**，输出真实 Pareto 前沿 |

**双目标适应度**：`combined = mIoU − λ·log10(cost / cost_base)`，λ = 0.02。

采用**对数成本**是必要的：本项目成本跨度约 25×（4 ~ 174 ms）。线性惩罚会一票否决全部低成本-中精度配置，而那正是 Pareto 前沿的左翼。

**成本模型**覆盖分支数、各分支几何参数、融合方式与特征宽度，并与实测锚点校准（比值 0.75 ~ 1.23，多数 < 5%）。

**工程保障**：所有实测统一走带重试的执行器；结果表的完成度以**单元数**判定而非文件存在性；验收表与搜索表在机制上隔离，确保 test 数字不可能回流到搜索。

## 3. 否证：结构超参层已被穷尽

### 3.1 架构表：主效应强，交互为零

6 个配置（k × 池化 × 图空间），**参数量全部相同 = 113,415**，12×12 房间交叉评估：

| 配置 | mean mIoU |
|---|---|
| `k=48 \| agg=max \| space=feat` | **0.3370** |
| `k=48 \| agg=max \| space=coord` | 0.3305 |
| `k=48 \| agg=maxmean \| space=feat` | 0.3125 |
| `k=48 \| agg=mean \| space=feat` | 0.2653 |

- **主效应显著**：池化 max vs mean 相差 **0.07**
- **交互为零**：逐房间 oracle = 最好单一配置（headroom **+0.0000**）；
  **6 个 Area 的最优配置全部相同**（域级 headroom 同为 **+0.0000**）

> **结论：收益来自"选一个更好的普通架构"，而非"让架构随条件变化"。**

### 3.2 三个独立角度确认条件化无空间

| 角度 | 结果 |
|---|---|
| 密度相关性 | R² = 0.008 |
| 尺度相关性 | R² = 0.018 |
| 类别数相关性 | R² = 0.001 |
| 逐房间 oracle 上限 | **+0.0017** < σ_fit 0.0014 |

### 3.3 结构族本身并未饱和

用两预算差值 Δ = full − cheap 诊断：

`r(cheap, Δ) = +0.809`（**正相关**）→ **优势放大型**：起点好的配置补涨更多，差距被训练**拉大**。

这说明**结构差异是真实的**，不是训练量差异造成的假象。（判据需同时看 Δ 极差与 r 符号：r ≈ −1 的欠拟合回填趋同才是真饱和。）

> 综合 §3.1–3.3：**问题不在"选哪个超参"，而在"用哪种几何表示"。**

## 4. 搜索空间与闭环

（方法细节见 §2。）本节给出空间的构成与规模。

- **表示族**：voxel（z 作为第三空间轴，稀疏 3D 卷积）/ pillar / range-view / points

- **融合方式**：late / gate / concat

**已实测架构数**：100+ 张结果表，覆盖人工枚举 88 个配置 + 闭环产出的进化架构。

## 6. 四条可复用的尺度规律

全部来自实测，且共同解释了"越多/越细越好"为何是错的。

### 6.1 z 分层数：倒 U，峰值 64

单尺度（体素 0.25 m）：

| z_bins | 8 | 16 | 32 | 48 | **64** | 96 | 128 | 192 |
|---|---|---|---|---|---|---|---|---|
| mIoU | 0.3290 | 0.3603 | 0.3780 | 0.3848 | **0.3885** | 0.3883 | 0.3813 | 0.3806 |

**物理原因**：过粗会把不同地物压进同一层（欠分辨）；过细则每层样本过少、房间高度被过度切分（过分辨）。

### 6.2 体素尺寸：倒 U，峰值 0.20 m

| 体素边长 | 0.50 | 0.35 | 0.25 | **0.20** | 0.15 |
|---|---|---|---|---|---|
| mIoU | 0.3685 | 0.3812 | 0.3848 | **0.3902** | 0.3879 |

### 6.3 收益来自"加分支"，不来自"调参数"

对同一冠军做单轴扰动：

| 扰动 | mIoU | Δ |
|---|---|---|
| **增加第 4 个分支** | **0.4147** | **+0.0021** |
| 粗端体素 0.50 → 0.35 | 0.4125 | −0.0001 |
| 粗端 z 96 → 128 | 0.4116 | −0.0010 |
| 粗端体素 0.50 → 0.25 | 0.4111 | −0.0015 |
| 粗端 z 96 → 64 | 0.4098 | −0.0028 |

**参数微调全部无效；只有增加尺度覆盖带来提升。**

### 6.4 收益不是来自堆参数

在参数量几乎相同的前提下（249,735 vs 251,975），架构选择的差距达 **2.7×**：

| 配置 | 参数 | Δ |
|---|---|---|
| `points_f128`（同族加宽） | 249,735 | +0.0191 |
| `voxel25_z64`（换几何表示） | 251,975 | **+0.0515** |

**同等参数预算下，改变几何表示远比加宽容量有效。**

## 7. 讨论：收益来源与适用边界

### 7.1 收益分解

```
points（kNN 动态图基线）                              0.3370   103.8 ms/step   3524 MiB
  + 换为 voxel 几何表示（z 作第三空间轴）              +0.0515
  + z 多尺度（并行多个 z 分辨率）                      +0.0103 ~ +0.0161
  + 体素尺寸优化（0.25 → 0.20 m）                      +0.0020
  + 混合体素尺寸（细 + 粗在同一网络内）                +0.0030
= 五分支冠军                                          0.4194
```

**几何表示贡献了增益的绝对主体（+0.0515，占约 63%）**，多尺度覆盖次之。这与 §1.2 的判断一致：感受野与密度解耦才是根本。

### 7.2 容量轴的边界：不同表示族的瓶颈位置不同

我们在 voxel 分支上测试了特征宽度，用以定位该表示族的精度瓶颈：

| 特征宽度 | mIoU | ms/step | 每单位成本的精度 |
|---|---|---|---|
| 32 | 0.4150 | **30.6** | 高（最经济的配置） |
| **64（冠军）** | **0.4194** | 39.5 | **最高** |
| 128（四分支） | 0.4154 | 117.4 | 低 |
| 128（三分支） | 0.4132 | 87.0 | 低 |

**结论清晰：在体素表示上，精度瓶颈不在容量。** 特征宽度从 64 提升到 128 需要 2.2 ~ 3.0× 成本，而精度不再提升；反向收窄到 32 可省 22% 成本，精度损失 0.0044。**64 落在效率最优处**，而该处正是本文搜索空间所选定的宽度。**这说明不同表示族的瓶颈位置不同**——在 kNN 动态图上加宽特征宽度收益可观，而在已获得几何解耦的体素表示上，**精度瓶颈已转移到尺度覆盖是否充分**，而非容量本身。因此在该表示族上，**把同样的算力投入几何与尺度的搜索，回报远高于加宽特征**。这一观察本身即支持本文的核心论点：搜索对象应是几何表示而非容量。

### 7.3 适用边界

- 本工作全部实验在 S3DIS 室内数据上完成；跨数据集泛化是自然的后续工作。
- 我们与 kNN 动态图骨干（DGCNN）在**同一训练协议、同一评价指标**下对比，从而将差异归因于表示与尺度，而非训练配方。
- 冠军配置的五个体素尺寸覆盖 0.15 ~ 0.50 m，对应室内场景中人-物-房间三个尺度层级；该配置的可解释性来自尺度覆盖的完备性，而非某个特定参数的奇巧取值。

## 8. 结论

我们重新定义了室内点云分割的架构搜索对象。
