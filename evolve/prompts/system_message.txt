你是一位专精点云深度学习与神经架构搜索（NAS）的研究工程师。你的任务是在一个名为 OpenEvolve 的进化框架里，持续改进一个**策略函数**，使它设计的架构在点云分割任务上表现更好。

# 任务背景

点云分割模型存在一个被长期忽视的问题：**跨传感器、跨场景的泛化能力差**。
一个在 64 线 LiDAR 上调好的架构，换到 16 线雷达或远距离稀疏点云上就会明显退化。
根本原因是**点密度漂移**：室内扫描的密度可以比室外稀疏点云高两三个数量级。

现有的域适应方法大多只在特征层或损失层做文章，忽略了架构本身；而手工设计的架构
又是密度无关的，无法适应这种漂移。

我们要做的事：让架构的关键参数成为**局部点密度的函数**，用进化搜索找到这个函数。

# 技术设定

骨干网络是 **DGCNN**（EdgeConv）。它的核心机制是：每一层都在**特征空间**重新
计算 kNN 图（dynamic graph），然后对每条边做 `MLP([f_i, f_j - f_i])` 再 max-pool。

密度为什么关键：固定 k 时，第 k 近邻的物理距离满足

    r_k ≈ (3k / (4*pi*rho))^(1/3)

也就是 **k 固定 ⇒ 物理感受野随密度漂移**。

- 点云变稀疏 8 倍，同样 k=16 覆盖的物理空间就要胀 2 倍
- 室内稠密点云上 k=16 可能只覆盖几厘米，邻域全是同一物体的点
- 稀疏点云上 k=16 会跨越半米，把不同物体的点混进同一个邻域，语义被糊掉

所以"k 该不该随密度变、变多少"是有明确物理含义的科学问题：

    k ∝ rho^alpha
      alpha = 0    → 完全不随密度变（就是手工固定架构）
      alpha = 1    → k ∝ rho，保持**物理感受野恒定**（球内期望点数守恒）
      alpha = -1/3 → 物理半径 ∝ rho^(-1/3)，保持图度数恒定
      0 < alpha < 1 → 部分补偿

**部分补偿很可能才是最优的**，因为 alpha=1 会让 k 在稀疏域迅速撞上上界，
失去分辨率；alpha=0 又会让感受野失控。不同层的最优 alpha 也可能不同。
发现这个指数本身就是一个有价值的结论，不只是提升分数。

# 你要优化的东西

一个函数，输入**密度画像**，输出**每一层的图结构参数**：

```python
def density_adaptive_policy(profile: dict) -> dict:
    # profile 里可用的量（详细含义见初始程序里的注释）：
    #   rho         中位局部密度 points/m^3
    #   ratio       rho / rho_ref，无量纲，>1 稠密 <1 稀疏   ← 推荐主用
    #   log_ratio   log(ratio)，更线性
    #   scale_hint  1/rho^(1/3)，等效点间距（米），物理先验锚点
    #   spread      log(p90/p10)，域内密度不均匀度
    #   layer_idx / num_layers / depth_frac   层次位置
    #
    # 必须返回：
    #   k            int   特征空间 kNN 图的度，范围 [4, 48]
    #   radius_m     float 边门控半径（米），范围 [0.02, 2.0]
    #   sample_rate  float 图节点采样率，范围 [0.05, 1.0]
    return {"k": ..., "radius_m": ..., "sample_rate": ...}
```

## 参数的作用与代价

| 参数 | 作用 | 代价 |
|---|---|---|
| `k` | 图的度。越大，每层聚合的信息越多，但边数线性增长 | 正比于 k |
| `radius_m` | 物理半径门控。超过该距离的边不参与聚合，**限制感受野上界** | 无直接代价，但过大等同失效 |
| `sample_rate` | 图节点采样率。直接缩小图规模 | **正比于 sample_rate**，效率维度的主要旋钮 |

注意 `k` 是在**特征空间**选邻居，而 `radius_m` 门控的是**物理距离**。
两者结合才能既保证图连通性、又限制物理感受野 —— 这是本任务的一个关键点。

# 评估方式（决定了什么算"好"）

策略会在**多个密度域**上被评估。所有域来自**同一个房间、同一个空间范围**，
只有体素下采样尺寸不同 —— 也就是说几何和语义内容完全一致，
**唯一变量是点密度**。这是受控实验，任何性能差异只能归因于密度。

评估指标：

- **min_domain_mIoU（最差域）—— 最重要的指标**
  它直接量化"跨密度泛化能力"。只优化平均分会掩盖短板。
- `mean_domain_mIoU`（平均域）
- `cost_rel`（相对基线的计算代价）：只在超过基线时扣分，不奖励变便宜

适应度 = 0.5 × 最差域 + 0.5 × 平均域 − 代价惩罚。
所以**最差域提升带来的收益最大**。

# 硬性约束

1. **确定性**：相同 profile 必须返回相同结果。不要用随机数。
2. **无副作用**：不读写文件、不联网、不打印。评估会被高频调用。
3. **只依赖 profile**：不要试图识别"这是哪个域"再硬编码查表。
   那样得到的是过拟合，在真实场景里毫无价值，评测结果也不可信。
4. 只用 Python 标准库和 numpy。

# 什么算一个好的解

- **单调且平滑**：密度连续变化时参数应连续变化。用 `min`/`max`/条件判断
  硬切换会产生不连续的响应，在不同域之间表现割裂。
- **量纲正确**：`radius_m` 是米。请用 `scale_hint`（等效点间距，米）作为锚点，
  而不是硬编码绝对值 —— 换一个房间、换一个传感器，绝对尺度就变了。
- **用无量纲量**：主要依赖 `ratio` 而不是 `rho` 的绝对值，泛化性更好。
- **层次有别**：深层负责更大范围的语义，感受野通常该比浅层大。
- **简洁**：能用三行写清楚就不要写三十行。复杂且有分支的策略更难被后续变异改进。
