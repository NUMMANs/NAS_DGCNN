# NAS_lidar

**跨域三维点云语义分割的神经架构搜索** —— 把搜索对象从"骨干超参"换成"几何表示与尺度"。

在 S3DIS 室内点云的跨房间基准上，自动搜出的架构把 mIoU 从 **0.3370 推到 0.4194**
（**+24.4% 相对**），同时训练**快 2.8×**、显存**省 5.2×**。

---

## 一句话概括

人类设计者把网络结构当作超参调（层数、宽度、聚合方式），本项目论证**真正有收益的
自由度在"几何表示与尺度"**：把点云转成什么形式（体素 / 柱状 / 球面投影的点）、
以及**每层用多大感受野**。用一个"提出 → 实测 → 写回"的真实评估闭环自动搜出结果，
**不依赖 LLM 估值、不依赖代理分数**。

---

## 核心结果

| 项 | 数值 |
|---|---|
| 基线（kNN 动态图） | 0.3370 |
| 自动搜出的冠军 | **0.4194**（+0.0824 = **+24.4% 相对**） |
| 训练速度 | **快 2.8×**（103.8 ms → 37.5 ms/step） |
| 显存 | **省 5.2×**（3524 MiB → 680 MiB） |
| 搜索空间 | **3.2×10⁸** 种组合（vs 人工枚举 88 个） |
| 证据规模 | **162 张结果表 / 4293 个实测 cell** |

**冠军架构**（**全部由闭环自动搜出，非人工设计**）：

```
voxel15_z16, voxel20_z24, voxel25_z16, voxel35_z64, voxel50_z96 @ gate
```

= **5 个不同体素尺寸**（0.15 / 0.20 / 0.25 / 0.35 / 0.50 m），**每层各自独立的 z 分层**
（16 / 24 / 16 / 64 / 96），用门控融合。test split 独立验收 **0.4210**，与 val 排序一致（非过拟合）。

---

## 四条实测规律（都来自数据，不是推断）

1. **z 分层是倒 U 形**，单尺度峰值 ≈ 64（voxel25：z8 0.3290 → z64 0.3885 → z192 0.3806）
2. **体素尺寸是倒 U 形**，峰值 ≈ 0.20 m
3. **收益来自"结构性新增"，不来自"参数微调"**
   —— 加第 4/5 个分支各 **+0.0021 / +0.0033**；而调粗端参数全部 **−0.0001 ~ −0.0028**
4. **"降 z"不普遍适用**：v25 降 z 是严格改进；但 v20 / v35 降 z **全部变差**
   → **每一层有各自的最优 z**，且**不同分支共存时该最优会移动**

**贡献分解**：体素表示 **+0.0515** → z 多尺度 **+0.0103~0.0161** → 体素尺寸 +0.0020 → 混合体素尺寸 +0.0030
**且不是堆参数**：`points_f128`（249,735 参数）只拿到 +0.0191，而 `voxel25_z64`（251,975 参数）拿到 +0.0515。

## 技术要点

### 真实的架构进化闭环（本项目的核心方法论产出）

前两轮搜索都**不是真进化**：一轮只能在 63 个预选点里挑名字；另一轮只有**估计精度**，
赢不过实测。补齐三个缺一不可的条件后才是：

| 条件 | 实现 |
|---|---|
| **空间够大** | 架构串语法，组合数 **≈3.2×10⁸** |
| **新架构能被真实评估** | 任意合法架构串**无需注册**即可训练 |
| **奖励无结构性天花板** | **成本可估，精度绝不估** —— 新架构精度标 `pending`，作为"待实测建议"返回 |

**方法论修正**：**选择用枚举，提出才用创造**。
候选池有限（~70）、目标确定 → **枚举就是精确解**。
实测：两轮 LLM 搜索的 best = 0.4216，**不如直接枚举的 0.4244**。

### 搜索对象 = 几何表示 + 逐层尺度

- **多分支几何表示**：点 / 柱状 / 体素（含手写稀疏 3D 卷积）/ 球面投影，支持门控 / 拼接 / 后融合
- **每分支独立的尺度参数**：体素尺寸、z 分层、投影分辨率
- 业界现有 NAS-for-3D 普遍假设"每个视图用**固定分辨率**" —— 本项目证明**该假设是错的**，
  收益恰恰来自**同一表示族内的多尺度混合，且每层尺度独立**

### 工程约束（硬性）

- **GPU 单卡纪律**：所有 GPU 操作钉在指定物理卡；代码层在**包导入时**（早于 `import torch`）
  设 `CUDA_VISIBLE_DEVICES` + 启动前容量守卫 + 进程显存上限，**不挤占同机其他作业**
- **跨环境依赖隔离**：evaluator 跑在**无 torch** 的环境，被其依赖的模块**模块级只依赖 numpy**，
  torch 在函数内延迟导入
- **每 cell 落盘**：任务可续跑，崩溃最多损失 1 个 cell（本项目训练进程有间歇性原生崩溃，
  靠"多轮重试 + 产物复核"而非 `returncode` 保证正确）

## 一批诚实的负结果

否证类结论同样有信息量，本项目系统性记录在案：

| 命题 | 判定 | 证据 |
|---|---|---|
| **按房间 / 按域条件化架构有收益** | ❌ | 逐房间 oracle = 最好单一配置；6 个 Area 最优全是同一配置（headroom **+0.0000**） |
| 最优 k 由密度 / 尺度 / 类别数决定 | ❌ | R² = 0.008 / 0.018 / 0.001 |
| **短预算代理能加速搜索** | ❌ | 25 ep 时 ρ = **−0.825**（负相关！），**50 ep 才 +0.943** |
| `regret` 口径能救短预算 | ❌ | 固定预算下它只是 mean 的仿射变换（ρ = +1.000） |
| **加宽特征（容量类轴）有收益** | ❌ | 花 2.2~3.0× 成本，精度**反而降** 0.004~0.006 |
| 球面投影（range-view）可用于室内 | ❌ | 单独最弱（0.2786）；分辨率扫描几乎平坦 → 瓶颈是**表示失配**，不是分辨率 |

## 代码结构

```
nas_ptseg/                 # 核心库（13.4k 行）
├─ gpu.py                  # GPU 硬约束：导入即钉卡 + 容量守卫 + 显存上限
├─ room_split.py           # 固定 train/val/test 划分 + 磁盘缓存
├─ metrics.py              # torch-free 指标
├─ arch_space.py           # 架构串解析 / 校验 / 成本模型（torch-free）
├─ arch_loop.py            # 进化闭环执行器：提出 → 实测 → 写回
├─ pareto_select.py        # 双目标精确解（枚举）+ 真实 Pareto 前沿
├─ multibranch.py          # 多分支几何表示 + 融合
├─ 三个骨干线
│   ├─ tier2_dgcnn.py      # DGCNN（可开关 feat/layers/agg/graph_space）
│   ├─ pointvig.py         # PointViG（论文无官方代码，按规格自建）
│   └─ pn_radius.py        # PointNeXt 半径轴搜索（当前主线）
└─ 诊断链 diag_*.py / saturation.py / headroom.py / reliability.py
                           # 逐层定位"不报错的静默错误"、判断某轴值不值得搜

evolve/                    # OpenEvolve 集成（API key 用 ${VAR} 占位，不入库）
docs/                      # 论文、工作报告、结果表、6 份 NAS 综述
```

## 快速开始

```bash
# 环境：conda lidar310（Python 3.10 + PyTorch 2.5.1+cu121）
python -m nas_ptseg.gpu              # 自检 GPU 约束
python -m nas_ptseg.selftest         # 跑内置自检
python -m nas_ptseg.smoke_multibranch # 烧 GPU 前的正确性冒烟
```

**依赖数据集**：S3DIS（室内点云，需自行放置，见 `.gitignore` 排除规则）。
